# 墨笺 Windows Desktop Product Contract

Last verified: 2026-08-27

Read this document before changing `Notein-win` storage, navigation, canvas input, desktop chrome,
import/export, or release packaging.

## Product boundary

This is the Windows edition of our own Android application, `墨笺` (`com.meta.inklab`, Android
v0.5.0). It is not a Notein Windows client and does not depend on Notein backup compatibility. Both
platforms own the same product concepts: notebooks, recursively nested sections, pages, view
settings, inserted objects/assets, logical ink colors, and the `mojian-notebook` / `mojian-section`
`.mjn` exchange boundary. Notein remains only a clean-room handwriting and interaction reference.

The desktop product must remain useful by itself: notebooks, recursively nested
sections, pages, ink, text, tags, inserted assets, search, export, and restart persistence are real
features. A successful build or a static OneNote-like window is not acceptance.

## Workspace and persistence

- A workspace is a user-controlled directory with `library.json`, `settings.json`, and one folder
  per notebook. The user can choose this directory so Syncthing can synchronize it.
- Android-compatible paths remain `notebooks/<notebook-id>/pages/<page-id>.json` and
  `notebooks/<notebook-id>/assets/<page-id>/`. Imported files are copied into page-owned assets before
  an object references them.
- Writes use a same-directory temporary file followed by atomic replacement. Corrupt JSON is never
  silently overwritten; the store preserves the damaged file and opens a recoverable empty model.
- IDs are GUID-based and stable. Persisted filenames use validated IDs only.
- Every mutation that changes document state is autosaved. Navigation saves the old page before
  loading the new page. Closing flushes pending state.
- Concurrent divergent revisions are not silently merged. The first synchronization version uses
  one active writer per notebook and keeps conflict copies generated by Syncthing.

## Desktop information architecture

The normal window uses four vertical zones after the ribbon:

```text
+----+--------------------+----------------------+---------------------------+
|rail| notebook/sections  | pages                | paper workspace           |
|32px| 196px, near-black  | 196px, dark gray     | unbounded or A4 sheets    |
+----+--------------------+----------------------+---------------------------+
```

- The black pane contains notebooks and sections only; the gray pane contains pages only.
- `本层` and `递归` page modes retain the Android contract. Selecting a deep recursive page does not
  move the black-pane root.
- `开始`, `插入`, `绘图`, and `视图` have separate ribbon panels. Controls never remain visible merely
  because a binding failed.
- Full-page mode hides tabs and collapses the rail column completely. It starts with both panes
  closed, leaves independent section/page recovery buttons, and keeps their open state transient so
  entering or leaving full page never rewrites the normal-workspace pane preferences. Its top
  controls remain clickable inside the 34 px native caption region and stay clear of DWM caption
  buttons. The 34 px canvas actions preserve the Android 24 x 24 icon viewport inside their border
  instead of clipping path geometry to the content box; the visible enter/exit glyph bounds are
  raster-checked against the button center rather than trusting WPF's nominal layout bounds.
- Split view owns two independent page slots. Leaving split view keeps the right slot.
- Backstage is a true full-screen surface with working notebook/workspace/export/options panels.
  Its shortcut panel follows the ribbon order and lists only immediate leaf actions; Xiaomi pen
  settings are Android-only and never appear here.

## Visual system

Port the current Android `墨笺` interface rather than designing a Windows-only skin. Preserve its
layout, compact icon-only ribbon, 32 dp rail, 196 dp navigation panes, small radii, and exact core
palette from `MainActivity`: title `#141414`, ribbon `#111111`, toolbar `#232323`, section navigation
`#0F0F0F`, page list `#2A2A2A`, workspace `#0A0A0A`, border `#3D3D3D`, selected lavender-gray
`#374048`, accent `#DAB2E9`, primary text `#F4F4F4`, and secondary text `#B9B9B9`.

Windows adaptations are limited to native title-bar behavior, keyboard focus, mouse hover/context
menus, scrollbars, pointer cursors, and accessibility. The 34 px top row reserves the Windows DWM
caption hit zone and uses the OS-owned minimize/maximize/close glyphs; it must not simulate them with
text or custom vectors. These adaptations must not reorder the Android product's navigation or
replace its established visual language.

Icon resources are generated mechanically from `android/app/src/main/res/drawable` rather than
redrawn from memory. Every source path keeps its full geometry; literal per-path colors remain a
multi-layer `DrawingImage`, while tintable single-color assets continue to inherit the WPF control
foreground. ADB screenshots of the installed Android build are the visual comparison baseline.

## Canvas and input

The normative device/state mapping is `docs/design/input-gestures.md`; this section records only
Windows-specific realization. Pen Hand/Lasso never changes mouse-left or touch-single semantics.

- Persist all completed ink in document coordinates with position, elapsed time, normalized pressure,
  tilt, tool type, logical color, width, opacity, and brush profile version.
- WPF stylus input uses real `StylusPoint.PressureFactor`; promoted mouse events must not duplicate a
  stylus stroke. Only a real stylus authors/erases ink. Mouse and touch use direct content handling:
  click/tap selects, a second click/tap on selected text edits, dragging selected content transforms
  it, and every other primary drag creates a containment marquee even when it starts over an object.
- Wheel/pinch zoom anchors to the pointer/centroid. The shared range is 50-800%. Holding the middle
  button pans; holding Ctrl with middle drag continuously zooms.
  Ctrl-drag is radial around the canvas center: dragging toward the center zooms out and dragging
  toward an edge zooms in, with the original contact point kept as the content anchor.
  A mouse or stylus side button remapped by its driver to middle button inherits this behavior.
  Holding middle is the only trigger required: moving the stylus while it is still in-air immediately
  pans. Pressing Ctrl while middle remains held immediately switches that same in-air movement to
  radial zoom; releasing Ctrl returns to pan without another middle click. No nib contact or second
  click is required.
  On this Windows Ink device the promoted mouse-compatible coordinates are the sole driver for that
  in-air navigation. After nib contact, the high-resolution stylus stream takes over and consumes only
  its newest coalesced sample; the mouse-compatible copy is then ignored so it cannot execute the
  motion twice. The same coordinates continue to refresh the nib position. Stylus Hand follows the
  same direction rule. Zoom lock blocks gesture scaling only.
- Pen Hand shows a hand cursor only while a real stylus is in range and makes that stylus pan.
  A real stylus in range uses a small screen-space nib dot for pen/highlighter authoring; ordinary
  mouse movement keeps its arrow and left-button content behavior even while Pen Hand is selected.
- Insert Space is the explicit exception: one-finger touch or real-stylus drag shifts content, while
  stylus and mouse hover both show its dashed position preview. Mouse-left remains direct-content.
- `Shift+wheel` pans horizontally and ordinary wheel pans vertically; these are fixed gestures, not
  user-configurable shortcut entries. The old cursor/text-insertion mode does not exist. A blank
  primary click/tap creates an uncommitted caret; the first valid character commits it, while focus
  loss, another operation, or page navigation removes an empty temporary box without Undo.
- Keyboard mappings are stored per workspace, categorized as `文件`, `开始`, `插入`, `绘图`, and `视图`,
  and resolve conflicts by removing the previous owner. Standard editing, undo/redo, search,
  full-page, delete-selection, and zoom defaults are provided. Outside native text editing,
  unmodified `Backspace` and `Delete` are reserved for deleting the current mixed selection.
- Pen rendering uses pressure and speed correction with start/end taper. Logical black remaps for dark
  paper without changing the stored color. The Windows wet layer never draws a visible extrapolated
  segment ahead of the pen-tip feedback dot.
- Whole-stroke eraser, pen freeform/rectangle lasso, direct-pointer rectangle marquee, mixed-content move, and eight-handle
  non-uniform scaling are document operations and participate in autosave. The eraser removes ink
  and tags but never treats inserted objects as strokes; immutable PDF page backgrounds also survive
  clear-page operations.
- Existing text, ink, tags, and non-background inserted objects remain directly selectable regardless
  of Pen tool state. Text follows Select -> Edit through ordinary clicks; canvas double-click is
  reserved. Right click selects the target and opens the same context surface as touch long press.
- Changing page or view state cannot leak content between pages.

## Insert and export

- Images, attachments, spreadsheets, stickers, PDF printouts, tables, and note links all use the
  page-owned asset/object model. Clicking an embedded file opens the copied asset, never the source.
  Image-like objects persist quarter-turn rotation, horizontal/vertical flip, stacking order, size,
  and background state. Cut/copy/paste reimports page-owned assets into the target page.
- The gray-pane `+` opens one dark Page/PDF dialog. Normal pages remember their last successful paper,
  baseline, and color without PDF imports overwriting that template. PDF page import uses the Windows
  PDF renderer, creates one immutable-background page per source page, retains the original PDF and
  rendered page asset, and preserves the source MediaBox dimensions in later layered export.
- PDF export is a light-theme visual share. The private `.mjn` ZIP uses Android's existing manifest
  identifiers (`mojian-notebook` / `mojian-section`, version 1) and carries editable JSON and original
  assets. Export never substitutes for autosave.

## Release acceptance

Release output is replaceable state, not an archive. Before publishing, remove every prior project-owned
release/candidate directory after confirming no delivered EXE is running. Publish only to
`Notein-win/artifacts/release`, then clean project-local `bin/obj`; do not retain parallel dated or
candidate copies. Reusable package caches and user workspace data are outside this cleanup boundary.

1. Start from an empty temporary workspace; create notebook, nested section, and pages.
2. Draw with mouse and stylus paths, add text/tag/table/image/attachment, navigate away and back.
3. Restart the release EXE and prove hierarchy, settings, content, assets, viewport, and appearance
   survived.
4. Exercise all ribbon tabs, both pane modes, pane toggles, full-page mode, split view, undo/redo,
   selection, page creation, search, and workspace switching.
5. Export a readable PDF and `.mjn`, then validate their structure.
6. `dotnet test`, Release build/publish, XAML binding-error capture, and a real window screenshot must
   pass before delivery.

  real window, a page was created, a sticker inserted, selected by rectangle lasso, moved using the
